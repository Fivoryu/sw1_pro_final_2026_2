CAPITULO 2 - PROCESO DE DESARROLLO DE SOFTWARE

Sprint 1

    1. Sprint Planning
El Sprint Planning permite organizar el trabajo que será desarrollado durante el Sprint 1,
estableciendo el objetivo del Sprint, las historias de usuario seleccionadas, los responsables,
los entregables esperados y el incremento funcional que deberá obtenerse al finalizar la
iteración.

Para este Sprint se priorizan las funcionalidades base del sistema, necesarias para que la
Plataforma Inteligente de Seguimiento Operativo y Productividad en Trabajo Remoto pueda
operar de manera inicial. Estas funcionalidades incluyen autenticación, gestión de usuarios,
roles, permisos, configuración de jornadas, registro de jornada laboral, consulta de historial,
estado de trabajadores, bitácora administrativa y notificaciones básicas.

El Sprint 1 constituye el primer incremento funcional del sistema, ya que permite construir la
estructura administrativa y operativa mínima sobre la cual se integrarán posteriormente los
módulos de monitoreo, navegación, inactividad, productividad, reportes, alertas y evidencias.

    1.1. Objetivos del Sprint

    1.1.1. Objetivo general del Sprint 1

Implementar el primer incremento funcional de la plataforma, compuesto por los módulos
de autenticación, gestión administrativa, configuración de jornadas, registro de actividad
laboral, historial, estado de trabajadores, notificaciones básicas y bitácora administrativa.

    1.1.2. Objetivos específicos del Sprint 1
    • Implementar el inicio de sesión para trabajadores desde la aplicación de escritorio.
    • Implementar el inicio de sesión para administradores y supervisores desde el panel

         web.
    • Permitir la creación, edición, consulta y desactivación de usuarios.
    • Aplicar control de acceso según los roles definidos en el sistema.
    • Permitir la configuración y asignación de jornadas laborales.

    2.1.2.3. Diseño Físico

-- =========================
-- 1. TENANTS (EMPRESAS)
-- =========================
CREATE TABLE tenants (

      id_tenant BIGSERIAL PRIMARY KEY,
      nombre VARCHAR(120) NOT NULL UNIQUE,
      slug VARCHAR(80) NOT NULL UNIQUE,
      estado BOOLEAN NOT NULL DEFAULT TRUE,
      creado_en TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- =========================
-- 2. ROLES (CATALOGO)
-- Nota: los permisos NO viven en BD, viven en codigo.
-- =========================
CREATE TABLE roles (

      id_rol BIGSERIAL PRIMARY KEY,
      codigo VARCHAR(30) NOT NULL UNIQUE,
      nombre VARCHAR(50) NOT NULL UNIQUE,
      descripcion VARCHAR(150),
      estado BOOLEAN NOT NULL DEFAULT TRUE,
      creado_en TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      CONSTRAINT chk_rol_codigo

             CHECK (codigo IN ('OWNER', 'ADMIN', 'SUPERVISOR', 'TRABAJADOR'))
);

-- =========================
-- 3. USUARIOS

                                                                                                             167
-- Un usuario pertenece a un tenant y tiene un solo rol.
-- =========================
CREATE TABLE usuarios (

      id_usuario BIGSERIAL PRIMARY KEY,
      id_tenant BIGINT NOT NULL,
      id_rol BIGINT NOT NULL,
      nombres VARCHAR(80) NOT NULL,
      apellidos VARCHAR(80) NOT NULL,
      username VARCHAR(50) NOT NULL,
      email VARCHAR(120) NOT NULL,
      password_hash TEXT NOT NULL,
       estado VARCHAR(20) NOT NULL DEFAULT 'ACTIVO',
      ultimo_login TIMESTAMPTZ,
      creado_por BIGINT NULL,
      creado_en TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       actualizado_en TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      CONSTRAINT chk_usuario_estado

             CHECK (estado IN ('ACTIVO', 'INACTIVO', 'BLOQUEADO')),
      CONSTRAINT uq_usuario_tenant_username

             UNIQUE (id_tenant, username),
      CONSTRAINT uq_usuario_tenant_email

             UNIQUE (id_tenant, email),
      CONSTRAINT fk_usuario_tenant

             FOREIGN KEY (id_tenant) REFERENCES tenants(id_tenant),
       CONSTRAINT fk_usuario_rol

             FOREIGN KEY (id_rol) REFERENCES roles(id_rol),
       CONSTRAINT fk_usuario_creado_por

             FOREIGN KEY (creado_por) REFERENCES usuarios(id_usuario)
);

-- =========================
-- 4. SESIONES
-- Login web / api / desktop
-- =========================
CREATE TABLE sesiones (

      id_sesion UUID PRIMARY KEY DEFAULT gen_random_uuid(),
      id_usuario BIGINT NOT NULL,
       canal VARCHAR(15) NOT NULL,
      ip VARCHAR(45),
      nombre_equipo VARCHAR(100),
      user_agent TEXT,
      token_refresh_hash TEXT,
      iniciada_en TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      expira_en TIMESTAMPTZ,
      cerrada_en TIMESTAMPTZ,
      activa BOOLEAN NOT NULL DEFAULT TRUE,
       CONSTRAINT chk_sesion_canal

                                                                                                             168
             CHECK (canal IN ('DESKTOP', 'WEB', 'API')),
       CONSTRAINT fk_sesion_usuario

             FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario) ON DELETE CASCADE
);

-- =========================
-- 5. CONFIGURACION DE JORNADA
-- =========================
CREATE TABLE configuraciones_jornada (

      id_config_jornada BIGSERIAL PRIMARY KEY,
      id_tenant BIGINT NOT NULL,
       nombre VARCHAR(80) NOT NULL,
      descripcion VARCHAR(200),
      tolerancia_min INTEGER NOT NULL DEFAULT 0,
      minutos_pausa INTEGER NOT NULL DEFAULT 0,
      estado BOOLEAN NOT NULL DEFAULT TRUE,
       creado_por BIGINT NULL,
      creado_en TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       actualizado_en TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      CONSTRAINT uq_jornada_tenant_nombre UNIQUE (id_tenant, nombre),
      CONSTRAINT chk_tolerancia_min CHECK (tolerancia_min >= 0),
       CONSTRAINT chk_minutos_pausa CHECK (minutos_pausa >= 0),
      CONSTRAINT fk_config_jornada_tenant

             FOREIGN KEY (id_tenant) REFERENCES tenants(id_tenant),
       CONSTRAINT fk_config_jornada_creado_por

             FOREIGN KEY (creado_por) REFERENCES usuarios(id_usuario)
);

AND hora_inicio < hora_fin)
      ),

    id_usuario BIGINT NOT NULL,

    id_config_jornada BIGINT NOT NULL,

    fecha_inicio DATE NOT NULL DEFAULT CURRENT_DATE,

    fecha_fin DATE,

    estado BOOLEAN NOT NULL DEFAULT TRUE,

    asignado_por BIGINT NULL,

    asignado_en TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario) ON DELETE CASCADE,

                     FOREIGN            KEY    (id_config_jornada)  REFERENCES

configuraciones_jornada(id_config_jornada),

    CONSTRAINT fk_uj_asignado_por

    FOREIGN KEY (asignado_por) REFERENCES usuarios(id_usuario),

    CHECK (fecha_fin IS NULL OR fecha_fin >= fecha_inicio)

HU-08         TITULO: Capturar proceso activo del sistema

       Descripción: Como trabajador, quiero que la aplicación de escritorio
       capture el proceso y la ventana activa en mi equipo, para que el sistema
       pueda registrar mi actividad durante la jornada laboral.

Prioridad: Alta Estimación: 5 PHU
Criterios de Aceptación

    • La aplicación toma una muestra del proceso/ventana activa cada 10 segundos
         (configurable).

    • Se registra el nombre del proceso (ej. chrome.exe), título de la ventana y
         timestamp.

    • Si no hay cambios entre muestras consecutivas, no se duplica el registro (se acumula
         tiempo).

    • El registro se almacena localmente y se sincroniza con el servidor al finalizar la
         jornada o en intervalos definidos.

Desarrollador a cargo: Letizia Mendieta Alban

HU-09       TITULO: Acumular tiempo de uso por aplicación

       Descripción: Como trabajador, quiero que el sistema acumule el tiempo
       de uso por cada aplicación que utilizo, para reflejar mi dedicación a
       distintas herramientas durante la jornada.

Prioridad: Alta Estimación: 3 PHU
Criterios de Aceptación

    • A partir de las muestras de proceso activo, se calcula el tiempo total por aplicación
         sumando intervalos.

    • Si una misma aplicación se usa de forma discontinua, se suman los períodos.
    • El tiempo acumulado se mantiene en memoria mientras la jornada está activa.
    • Al pausar la jornada, se detiene la acumulación; al reanudar, continúa.

              FOREIGN KEY (id_rol) REFERENCES roles(id_rol),

    1. Sprint Planning

    1.1. Objetivos del Sprint

         1.1.1. Objetivo general del Sprint 3
Implementar el tercer incremento funcional de la plataforma, compuesto por los módulos de
reportes, dashboards, alertas automáticas, gestión de evidencias, comunicación operativa,
ubicación referencial y funciones avanzadas de supervisión. Este Sprint busca consolidar la
información recolectada durante las jornadas laborales para transformarla en indicadores,
reportes y alertas que permitan al supervisor y administrador tomar decisiones oportunas
sobre el desempeño, la productividad y el comportamiento operativo de los trabajadores
remotos.

         1.1.2. Objetivos específicos
    • Implementar la detección de eventos sospechosos mediante reglas de inactividad y

         uso de aplicaciones no laborales.
    • Desarrollar un motor de alertas automáticas que notifique al supervisor cuando se

         presenten situaciones relevantes.
    • Permitir la configuración de reglas de alerta mediante umbrales definidos por el

         administrador.
    • Generar, almacenar y consultar evidencias asociadas a eventos sospechosos,

         considerando consentimiento, privacidad y viabilidad técnica.
    • Calcular indicadores generales de supervisión, como trabajadores activos,

         productividad media, alertas activas y eventos recientes.
    • Construir un dashboard con tarjetas, gráficos y resúmenes operativos para apoyar la

         toma de decisiones.
    • Generar reportes en PDF y Excel con información de actividad, inactividad,

         productividad, alertas y evidencias.
    • Implementar la comunicación operativa entre supervisor y trabajador mediante

         mensajes y notificaciones en la aplicación de escritorio.
                                                                                                             291
• Registrar y visualizar la ubicación referencial del trabajador, cuando exista
    autorización correspondiente.

• Implementar funciones avanzadas de cámara únicamente con consentimiento
    explícito, autorización institucional y cumplimiento de criterios legales.

• Consolidar el panel de supervisión como herramienta de análisis, seguimiento y
    control operativo del trabajo remoto.
