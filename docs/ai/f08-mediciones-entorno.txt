## 2. Condiciones: lo que NO está controlado

Se declara para que nadie lea estos números como un benchmark:

1. **Sin control de carga.** Las corridas se hicieron con la máquina en uso normal (Docker Desktop, editor, servicios abiertos). No se fijó afinidad de CPU, prioridad ni se apagó nada. Las latencias son **indicativas**, no reproducibles al milisegundo.
2. **Memoria compartida.** El contenedor corre dentro de la máquina virtual WSL 2 de Docker Desktop. Los 5.8 GiB declarados son los que el contenedor **ve**, no la memoria del host (15.6 GB). Ningún otro contenedor estaba ejecutándose durante la inferencia, porque cada corrida usa `run --rm`.
3. **Memoria residente pico.** `peak_rss_mb` (541 MB) mide el proceso de Python, no el consumo del motor de Docker ni el del sistema operativo.
4. **Sin GPU.** Ninguna medición usa GPU; memoria y utilización de GPU quedan **no medidos**, declarados así en cada registro.
5. **Un sólo equipo.** Todo lo medido es de esta máquina. No se extrapola a un despliegue, a un teléfono ni a otro hardware.
6. **Determinismo.** El detector es determinista en CPU: repetir la corrida con el mismo código devuelve las mismas etiquetas, puntuaciones y cajas. Lo único que cambia entre corridas es la latencia.
